# LC07-B0 disposable owner fixture

Explicit owner-approved test-only provisioning for the retained LC07 target. No server route, generic role API, production migration or signup-role change. `test/lc07b0` is excluded from production binaries. Normal tests skip provisioning; offline ownership/DSN denial tests still run.

The coordinator creates a new isolated project/network, empty Auth/RBAC/User stores, owner schemas and narrow bootstrap principals. Private mode0700 directory contains mode0600 ownership.json, owner-bootstrap.json and independent actor passwords. Never read sibling .env. Marker fixes run, network, nonce, short expiry and exact LC07 instance/submission. Database comment must equal the marker ownership digest before mutations; effective pgx config is checked and PG environment/fallback/options denied. No token signing capability in the fixture.

Only fixed run-derived admin, student and teacher identities exist; the latter two are negative probes. No arbitrary identity/role argument. Auth owns bcrypt/credential + scoped identity provenance and calls the actual existing User provisioning RPC after RBAC readback. RBAC owns only exact global/core grants. New disposable DB grants limit fixtures to INSERT/SELECT, never UPDATE/DELETE. Exact replay verifies unchanged identity/credential/binding and receipt; conflicts fail closed. No existing account promotion/reset. Private artifacts/DB checkpoints stay0600; do not log passwords/hashes/tokens/DSNs.

Owner commands (requires explicit disposable lifecycle permission): `LC07_B0_ENABLED=true LC07_B0_DIR=<private task directory> go test ./test/lc07b0 -run TestProvisionDisposable -count=1`. Run RBAC first, then Auth with actual User/RBAC broker owners. Offline: `go test ./test/lc07b0 -run TestOwnershipGuards`. The infrastructure coordinator must validate real Docker project/network/volume labels and perform independent Auth/User/RBAC readback. This fixture does not authorize APPROVE; LC07-B0 must never send it.

The canonical ownership digest includes every marker field, including expiry and both endpoint ports. Renewed/changed authority cannot reuse the existing database comment or private receipt. All existing Auth credentials are validated before any User RPC. The coordinator must independently establish the new User database ownership and empty/exact-owned ID/email/profile preconditions, then verify exact persisted User ID/email/one-profile after RPC; an RPC ack alone is not proof. Abort on any mismatch.
